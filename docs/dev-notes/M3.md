## RPC cho tab Tasks (FR-UI-07) — chữ ký ỔN ĐỊNH

`task.list` params (đều tuỳ chọn):
`{team: str, status: str | [str], assignee: str, origin: str (task gốc đã tách), include_archived: bool, limit: int = 200}`
→ `list[TaskRow]`, sắp theo `priority DESC, created_at ASC`. `TaskRow`:
```
{id, team_id, assignee_agent_id, role, kind ("task"|"root"), title, status, priority, created_by,
 origin_task_id, decomposed (0|1), current_run_id, consecutive_failures, attempts, block_reason, wait_reason,
 not_before, result_summary (cắt 300 ký tự), created_at, updated_at, started_at, done_at,
 parents: [task_id], children: [task_id], cost_usd (tổng run của task)}
```
`status` ∈ `triage | todo | ready | running | review | done | blocked | archived`.
`wait_reason` (task `ready` chưa được claim) ∈ `workspace_locked | budget | estop | team_estop | concurrency | agent_busy |
agent_paused | rate_limit | backoff | no_assignee | member_limit` (hoặc null).

`task.get` params `{id}` (id hoặc tiền tố duy nhất) → `TaskRow` + :
```
{body, workspace, overrides, result_schema, result_json, max_retries, idempotency_key,
 parents: [{id, title, status}], children: [{id, title, status}], subtasks: [{id, title, status, assignee_agent_id}],
 comments: [{id, author, kind, text, run_id, created_at}],
 runs: [{id, agent_id, kind, status, outcome, cost_usd, queued_at, started_at, ended_at, session_id, parent_run_id}]}
```
`team.list {include_archived?}` → `[{id, name, charter, policies, estop, estop_reason, archived_at, members: [{agent_id, role,
max_in_progress}], counts: {status: n}, cost_today_usd}]`; `team.get {id}` → như trên + `members[].agent_status`,
`cost_week_usd`, `budget_remaining_usd`.

Event để làm mới tab: `task.created`, `task.status` (payload `{task_id, from, to, reason}`), `task.comment`,
`task.circuit_open`, `task.decomposed`, `team.*`. Envelope có `task_id`/`team_id`.

### Dispatcher (FR-TK-05..10, 12, 13; FR-RT-16; FR-OB-03) — `dispatch/`
- Tick mỗi `tasks.tick_s` (5 s) + `kick()` khi có sự kiện. Kết quả run qua listener bus → `call_soon`, idempotent
  (`task.current_run_id == run.id`). Chi tiết trong docstring `dispatch/dispatcher.py`.
- **Claim nguyên tử**: `UPDATE … WHERE status=? AND current_run_id IS NULL` trong `BEGIN IMMEDIATE` (test 8 kết nối song song).
- Lý do chờ (`wait_reason`): estop/team_estop/budget:{hub,team,agent}/agent_paused/agent_busy/member_limit/concurrency/
  rate_limit/workspace_locked/backoff/no_assignee/no_lead.
- **Retry**: run mới có `parent_run_id`; `crashed|timed_out|rate_limited` → `--resume <session cũ>` + lời nhắc tiếp tục.
  Circuit breaker `failure_limit` → `blocked` + `task.circuit_open`. `rate_limited` không tính lỗi, backoff 30 s ×2 tới 600 s.
  `budget_exceeded`/auth → `blocked` ngay. ESTOP `--stop-running`/daemon restart → task về `ready` (không tính lỗi).
- **Outcome mới của run** (`runs.py`): `crashed` (tiến trình chết, không `result` — trước là `failed`), `rate_limited`
  (429/529/"rate limit"), `blocked` (agent gọi `task_block`), `protocol_violation`. Crash → dọn process group.
- **Lease/heartbeat**: heartbeat = event mới từ stdout (ghi `runs/tasks.last_heartbeat_at|lease_expires_at` tối đa mỗi 5 s);
  tick: tiến trình chết (returncode / `kill -0`) quá `lease_ttl_s` không heartbeat → dừng → `crashed`. Run đã kết thúc mà
  chưa xử lý (daemon chết giữa chừng) → xử lý ở tick.
- **Định tuyến** (`routing.py`): task team không assignee → worker có role/description khớp nhất (token hoá, bỏ dấu tiếng
  Việt, gốc từ thô), hoà → ít tải nhất; `default_assignee` khi không khớp.
- **Lead tách việc**: run `kind=lead` với `--json-schema` `PLAN_SCHEMA` (`{summary, subtasks:[{key,title,body,assignee?,
  role?,parents[]}]}`), lấy `result.structured_output`; hub kiểm lại (key trùng, cha lạ, chu trình, assignee lạ → dùng làm
  role). Sai → run `protocol_violation`, task gốc `blocked`, không tạo task con. Lead cũng tạo được task con qua hub-self.
  Task gốc `running` tới khi mọi con `done` → `done` với `result_json = {subtasks:[…], final: <kết quả task lá>}`;
  con `blocked` → gốc `blocked`.
- **Review** (FR-TK-12): `review_required` → `review` → run `kind=review` (reviewer/verifier ít tải nhất, không phải worker
  đó) với `REVIEW_SCHEMA {verdict, comment}`, cấm Edit/Write/MultiEdit/NotebookEdit, không khoá repo. `request_changes` →
  comment + Signal `reject` cho run của worker + `ready`; quá `max_review_rounds` → `blocked`.
- **Ngân sách ngày**: hub (`budget.hub_usd_per_day`), team (`policies.budget_usd_per_day`, cost = Σ `runs.cost_usd` có
  `team_id` kết thúc hôm nay), agent (`limits.budget_usd_per_day`). Trần `--max-budget-usd` của run = min(per-run, phần còn
  lại). Đạt 80% → `budget.warning`; 100% → `budget.exceeded` (1 lần/ngày/phạm vi), không claim (`wait_reason=budget:*`),
  `run.submit` có team → `Blocked`.
- **Rate limit**: `rate_limit_event` → `hub_state.rate_limit` (`throttled` khi status ≠ allowed hoặc utilization ≥ 0.9) →
  `RunManager.effective_limit()` = `ratelimit.throttle_concurrency` (1); event `ratelimit.throttle`; `hub.status.rate_limit`.

### Workspace repo thật (FR-RT-12) — `workspace.py`
- `WorkspaceLocks` (thay `guard/locks.RepoLocks` trong `RunManager`, cùng giao diện): khoá = gốc repo git của cwd
  (thư mục con cùng repo dùng chung khoá); không phải git → realpath. Theo SESSION → giữ qua `waiting_human`.
  Run chỉ đọc (`run_opts.read_only`, agent `permission_mode=plan` hoặc `tools` không có Bash/Edit/Write…) không khoá.
- Checkpoint trước run (`HUB_HOME/checkpoints/<run>/checkpoint.json` + `runs.checkpoint`): HEAD, nhánh, file chưa commit
  + bản sao nội dung (sha256, ≤ `workspace.max_file_bytes`). Không commit/stash/đổi gì.
- Diff sau run (trước event kết thúc run): file khác trạng thái trước run (so với bản sao dirty hoặc blob HEAD cũ) →
  `runs.diff` (files, stat, commits_made) + `diff.patch`; event `workspace.diff`; `hub_run_status.diff`.
- `agent-hub run revert <run> [--dry-run]` / `run diff <run> [--patch]`: chỉ khi mọi file vẫn như lúc run xong, ngược lại
  `Conflict` liệt kê file. Đã revert → từ chối. Session còn chạy / repo bị run khác khoá → từ chối. Thay đổi chưa commit
  của người (trước run) giữ nguyên. Không phải git → chỉ danh sách file, cảnh báo khi tạo task.
- Run bị gián đoạn (daemon restart) mà người đã sửa file của run → recovery KHÔNG resume (event `error
  workspace_changed`), task `blocked`.

## 3. Lệch BRD / quyết định riêng
- `crashed` thay `failed` cho run chết không có `result` (BRD FR-TK-05 có `crashed`). Lỗi spawn vẫn là `failed`.
- Kết quả tổng hợp của task gốc là tổng hợp CƠ HỌC (nối summary + `final` = task lá), không có run lead tổng hợp lần 2.
- Mặc định không bắt buộc gọi `task_complete` (BRD gợi ý `protocol_violation`) — giảm thất bại giả với model nhỏ; bật bằng
  `tasks.require_completion_call`. Chưa có "lượt nhắc qua resume" trước khi đánh dấu vi phạm.
- `hub_events` theo task là `hub_events(task_id=…)` (BRD liệt kê), event run của task được gắn `task_id`/`team_id`.
- Team: `teams/<id>/{memory.md, skills/}` tạo sẵn (M4 dùng). `team purge` (phá huỷ) chưa làm — chỉ archive/restore.
- Liveness dùng returncode/`kill -0` của tiến trình con trực tiếp (không thể tái sử dụng pid trước khi reap); `(pid,
  start_time)` vẫn dùng ở recovery sau restart.
- `--worktree` chỉ truyền cờ (`workspace.kind=worktree`), chưa kiểm với CLI thật; không checkpoint/khoá cho worktree.
- Checkpoint bỏ qua file bị `.gitignore` (thay đổi ở đó không vào diff, không revert).
